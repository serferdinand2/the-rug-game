# Architecture

The project's modules in detail, with the issue that added each. CLAUDE.md keeps a short map of the folders and links here. Claude and Codex update this file when a module is added, renamed or removed (see AGENTS.md).

## Modules

- **The backend** sits in two folders: `server/` (the HTTP server and its limits) and `api/` (the table API and the table rules it serves).
- `server/server.mjs` is the `node:http` server.
  - It exports `server` and `config` and only calls `listen()` when run directly, so tests start it in-process on port 0.
  - It serves files only from `build/`, resolving decoded paths and refusing anything outside the folder.
  - Vite's hashed bundles in `assets/` are cached for a year (`immutable`), and `fonts/`, `art/` and `audio/` for a week. Everything else, including the page, gets `no-cache` with a weak ETag, so a new deploy is picked up at once.
  - `/api/*` requests pass a per-address rate limiter (1,800 a minute) and go to the table API in `api/api.mjs` (#23).
- `api/api.mjs` is the table API (#23): `createApi(config)` keeps every table, guest session and long-poll request in memory, and serves `api/rooms.mjs`.
  - **Endpoints:** `config`, `tables`, `login`, `me`, `create`, `join`, `state` (`?since=<version>&seat=<n>`), `configure`, `settings` (#24), `add-seat`, `remove-seat`, `ready` (#25, no version), `start`, `end`, `move`, `undo` (#24) and `leave`.
  - **Timers (#24):** each table has one timer, set from `nextDeadline(room)`. `commit()` brings the room's clocks and declines up to date (`tick`) in the same commit as each change, and sets the timer again. When it fires, `playDue()` runs `timeout` and commits only if something progressed. Timers are `unref()`ed and cleared when a table closes or expires and when the server closes (`api.close()`). `config` gains `minuteMs`, `declineMinMs` and `declineMaxMs`, so tests shorten the waits. The design is `docs/superpowers/specs/2026-10-26-timer-and-undo-design.md`.
  - **Changes:** every change goes through `commit()`, which bumps the table's `version` and answers the requests waiting on it; a change carrying a stale `version` gets 409.
  - **What leaves the server:** rooms leave only through `roomView()`, so no person id, token or raw game ever does.
  - **Sessions:** bearer tokens; a session sits at one table at a time.
  - **Limits:** they sit in `config` (exported from `server/server.mjs`), which the API reads on every use, so tests shorten waits and raise limits there. The design is `docs/superpowers/specs/2026-10-26-server-api-design.md`.
- `server/limits.mjs` holds `rateLimiter()` and `clientAddress()`. With `TRUST_PROXY=true`, the last `X-Forwarded-For` address counts; otherwise the header is ignored.
- `api/rooms.mjs` holds the table rules (#22) as pure transitions in Bird Table's style: `createRoom`, `configure`, `join`, `addSeat`, `removeSeat`, `leave`, `start`, `end` and `play`, plus `settings`, `undo`, `timeout`, `tick`, `nextDeadline`, `scopeOf`, `phase`, `seatsOf` and `cleanName`. #25 adds `ready` (a seat's readiness in an online lobby, cleared by a host change). #29 adds `deal` (0 before the first deal, 1 more at each `start`, in the room view), so the client tells a new deal from the old game. #24 adds `TIMERS` (off, 1, 2 and 5 minutes), `HISTORY_LIMIT` (20 undo steps) and `AUTO_LIMIT` (1,000 automatic answers in a row), and the room fields `timer`, `undo`, `clocks`, `declines` and `history`. Each returns a new room, or `null` when it closes, and throws the engine's `PlayerError`. The code says room, players see table. For the server's `Map` of rooms it has `newCode`, `addRoom` (`MAX_ROOMS` 1,000), `expireRooms` (`ROOM_IDLE_MS`, a day), `openTables` and `unfinishedSeat`. Room seat `i` is game seat `i + 1`; seats never move or disappear while a game is on the table. It uses the engine only through `src/lib/engine/game.js`, whose `checkOptions()` checks a table's options.
- **Client.** The browser interface is **Svelte 5** with runes forced on (5.57.2), built by **Vite** (8.3.4), without SvelteKit. The project root is Vite's root, laid out like the owner's other Svelte projects (owner, 2026-10-21). The full layout is in docs/conventions.md.

Read the sibling projects' `CLAUDE.md` files before scaffolding (#1). The patterns to reuse:
- **Code:**
  - Node.js 22.12+ (the floor Vite 8 sets) and ES modules. No runtime packages on the server or in the engine. The Svelte client is the one exception with a build step.
  - A DOM-independent rules engine shared by the server and the browser.
  - `createGame()`, and `play()`, which returns a new state from a `structuredClone`.
  - `PlayerError` for messages meant for players.
  - Typed events with an increasing `seq`.
- **Server:**
  - `server.mjs` on `node:http` keeps rooms in memory.
  - Every response goes through `view()`, which hides private information.
  - Clients long-poll `GET /api/state?since=<version>`, and stale moves are rejected with 409.
  - `limits.mjs` holds the rate limits, and `.env` holds `HOST`, `PORT` (3020 here) and `TRUST_PROXY`.
- **Tests:** Vitest for the Node suites and Playwright in Chromium for the browser, set up as SurveyPlanet's `svelte_components` runs its own (#55), with randomized invariant tests for the engine and the rooms, also run in GitHub Actions.
- **Look:**
  - Cinzel for the names of game things and Atkinson Hyperlegible for everything else, with the roles in `docs/ui/README.md`. The single copies, with their licence notices, are in `static/fonts/`. The HTML mockups still load them from Google Fonts.
  - `src/styles/tokens.css` is the single source of truth for the look. Where the mockups disagree with it, for example the lobby's player colours, follow `tokens.css`.
  - The superseded Alagard and VCR OSD Mono fonts live only in `docs/ui/archivedpngmockups/fonts/`, for the archived mockup.
  - Art production notes stay in `docs/art/`, never in `build/`.
