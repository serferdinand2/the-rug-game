# Landmarks and the asset gallery (issue #7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the asset gallery in `art/preview/`. Then draw all 33 landmarks twice: a 64×64 card picture, and a top-down board piece that covers exactly its footprint.

**Architecture:**
- The gallery is a self-contained HTML page generated by `art/preview/build.mjs`. It replaces `art/preview.mjs` and its sheet.
- Footprints are plain data in `art/footprints.js`, with a checker that both the build and the tests use.
- Drawings follow the toolkit's existing pattern, one `draw()` module per id. The build refuses a board piece that doesn't match its footprint, as it already refuses an illustration that isn't 64×64.

**Tech Stack:** Node.js 22.12+ built-ins, the `art/` toolkit from #4, `node:test`, and svelte-check for JSDoc.

**Spec:** [docs/superpowers/specs/2026-10-21-landmarks-design.md](../specs/2026-10-21-landmarks-design.md), which builds on [2026-10-21-art-toolkit-design.md](../specs/2026-10-21-art-toolkit-design.md).

## Global Constraints

- **Toolkit rules** from #4 and `docs/art/README.md`:
  - JSDoc and ES modules, no runtime packages, and no `node:` imports in `art/**/*.js`;
  - a one-line comment at the top of each file;
  - braces on every `if`/`else`, and Prettier formatting;
  - `npm run check` with 0 errors and 0 warnings.
- **Drawing rules.**
  - No `Math.random()`; each drawing uses one `seededRandom(seed)` stream.
  - Colours are lowercase `#rrggbb`. Scene parts paint only `PALETTE` colours, and new colours go into `PALETTE`.
- **Ids** come from `art/catalog.js`:
  - a picture is `art/drawings/landmark/<slug>.js`;
  - a board piece is `art/drawings/landmark-marker/<slug>.js`.
- **Card pictures** are exactly 64×64. The build already enforces it.
- **Board pieces** use 16 pixels per plot, in the footprint's printed orientation (top row first, never mirrored).
  - Every pixel in an occupied plot is filled, and every pixel in an empty plot is empty.
  - A courtyard or yard inside the footprint is drawn as ground, never left transparent.
- **The Lighthouse picture** (`landmark/lighthouse`) is unchanged.
- **Subjects and times of day** come from the spec's §6.3 table. Each picture is our own interpretation, never a copy of Stonemaier's miniatures or card art.
- **Commits** say "Refs #7: …" with the `Co-Authored-By` line. #7 closes with "Fix #7: …" only after the owner approves all 33 in the gallery.

## Review Focus

1. **A board piece that is the right size but drawn transposed** (rows and columns swapped). For a non-square footprint such as the Launch Pad (`XXX/XXX`) or the Rubber Works, the piece would be wrong on the board. Task 2's checker compares the canvas size with `columns × 16` by `rows × 16`, and the build refuses a mismatch.
2. **A gap inside a footprint**, such as a transparent courtyard or an unfilled roof edge, so the piece covers fewer plots than it claims. Task 2's checker requires every pixel of every occupied plot, and its test pins it.
3. **The gallery opened straight from disk.** Any external file reference (a stylesheet, a script, an `<img src>`) breaks under `file://`. Task 1 has a test that the page has no `src=` or `href=` attributes and no `<link>` or `<script>` tags.
4. **Names with HTML-special characters**, such as "Sewage & Plumbing", "Wizards' Guild" and "Black die: tile benefit (?)", must be escaped in the gallery. Task 1 has a test that `Sewage &amp; Plumbing` appears and a raw `& ` doesn't.
5. **A drawing a contributor forgets to add to a batch**, which would let #7 close incomplete. Task 5's completeness test covers all 33 pictures and all 33 board pieces against the catalog, not a hand-written list.

### Task 2: Footprints and the board-piece check

**Files:**

  - `docs/superpowers/specs/2026-10-20-the-rug-game-design.md` (§6: the markers move from item 5 to item 7).

**Interfaces:**
- Produces (from `art/footprints.js`, with no imports):
  - **`PLOT_SIZE = 16`.**
  - **`FOOTPRINTS`:** a frozen `Record<string, readonly string[]>` from landmark slug to rows, exactly the spec's §6.1 table, top row first.
  - **`footprintMismatches(canvas: { w: number, h: number, p: (string | null)[] }, rows: readonly string[]): string[]`** returns `[]` when the canvas matches. Otherwise it returns one message per problem:
    - `` `canvas is ${w}×${h}, expected ${cols * 16}×${rows.length * 16}` ``, the only message when the size is wrong;
    - `` `plot (${col}, ${row}) is in the footprint but pixel (${x}, ${y}) is empty` ``;
    - `` `plot (${col}, ${row}) is outside the footprint but pixel (${x}, ${y}) is filled` ``.
    - It reports at most the first offending pixel per plot.
- Produces (from `art/build.mjs`): `buildArt` throws `` `${id}: the board piece doesn't match its footprint: ${first message}` `` for a `landmark-marker` drawing whose `footprintMismatches` isn't empty. The check runs before anything is written, like the size check. A `landmark-marker` drawing whose slug has no footprint throws `` `${id}: no footprint for this landmark` ``.
