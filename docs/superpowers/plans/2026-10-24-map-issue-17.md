# Exploring and conquering (#17) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `explore`, `exploreSpace`, `conquer` and `tileBenefit` work for real, with the defender's response question for traps, so tiles, outposts and the conquer dice play as the rules say.

**Architecture:** `map.js` holds the pure map rules: which hexes a player may explore or conquer, a hex's corners, and the matching sides. `effects/explore.js` and `effects/conquer.js` hold the effect handlers and the automatic `conquerDice`, and five decision kinds ask the players. The response question sits between the topple and the dice, so later expansions add steps around it.

**Tech Stack:** Plain Node ES modules with JSDoc, `node:test`, `node:assert/strict`.

**Spec:** `docs/superpowers/specs/2026-10-24-map-design.md`

## Global Constraints

- Engine modules import only relative paths: no DOM, Svelte or Node, and never `Math.random` (`tests/engine-data.test.mjs` checks). Randomness is `ctx.random(n)`, a whole number from 0 to n − 1.
- Prettier (tabs, single quotes), braces on every `if`/`else`, a one-line comment at the top of every file, JSDoc on every export. `npm run check` reports 0 errors and 0 warnings.
- `play()` stays pure. Player mistakes throw `PlayerError` with the exact sentences below; anything else is a plain `Error`.
- One event per thing that happened. No decision kind in this plan has hidden fields: `hidden: []`.
- Handlers never replace `state.pending` or a lane's stack array; they use `ctx.push`.
- Hex keys are BGA's axial `a_b`. `orient` is 60° clockwise steps, 0–5. A territory turned by `orient` shows its printed corner `(k − orient) mod 6` at position `k`.
- Terrain ids are the words in `data/ids.js` (`'sea'`, `'desert'`, `'forest'`, `'grassland'`, `'mountain'`).
- A pick with exactly one legal option is made automatically, without a decision.
- Cite rule ids in comments and test names (R5, R8, R16, R17, R21, R105, R107, R108, FAQ #18–20).
- `tests/helpers/engine.mjs`'s `stubHandoffs()` throws once a stood-in kind is built, so the task that registers a kind removes its stand-in from `HANDOFF_EFFECTS` and migrates every test that relied on it, in the same commit. Migrated tests assert real behaviour; they aren't deleted.
- Every new decision kind gets a fixture in the shape test in `tests/engine-final-fixes.test.mjs` (one entry per kind) in the task that adds it.
- Commits reference the issue: `Refs #17: …`, and the last one `Fix #17: …`. End every commit message with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**PlayerError sentences (exact):**

| Decision | When | Sentence |
|---|---|---|
| `chooseExplore` | the answer isn't one of `answers()` | `You can't explore there.` |
| `chooseConquer` | the answer isn't one of `answers()` | `You can't conquer there.` |
| `chooseDie` | `die` isn't `'red'` or `'black'` | `Choose one of the two dice.` |
| `chooseSpaceTile` | `tile` isn't one of the options | `Choose one of the space tiles offered.` |
| `chooseResponse` | `card` isn't `null` or a response card in the hand | `You can't play that card as a response.` |

## Review Focus

- **The response question must not leak.** The attacker's `view()` must be identical whether the defender's one card is a trap or another card: the same decision, the same events, no answers. Test in Task 5.
- **A territory controlled through a toppled-and-upright pair** (2 items) can never be conquered, explore adjacency still counts it, and the toppled owner gains nothing from it. Test in Task 4.
- **Answers that aren't in the list**, such as a hex string off the map, `orient: 6`, `tile: '5'` or a missing field, are refused with the table's sentence, never a crash. Test in Tasks 2 and 4.
- **Supplies running out.** No territory tile in hand, no space tile in supply, no outpost left: each does nothing and leaves no decision open. Test in Tasks 2, 3 and 4.
- **The response question during a real advance turn.** The defender's decision is open while it is the attacker's turn, nobody else can answer it, and the attacker's dice wait for it. Test in Task 5.

### Task 1: The map rules

**Interfaces:**
- Produces, in `map.js`:
  - `cornersOf(state, hex) → TerrainId[] | null`: the 6 printed corners of the territory on that hex: from `TERRITORY_TILES[tile − 1]` for tiles 1–48, from `MAPS[state.map].printed[hex]` for 49–77, and `null` while unexplored.
  - `turned(corners, orient) → TerrainId[]`: the corners in position order, `turned[k] = corners[(k − orient + 6) % 6]`.

  - `exploreHexes(state, player, anywhere) → string[]`: the unexplored hexes of the table's map side, in `MAPS[state.map].hexes` order. Without `anywhere`, only those next to a territory in `controlledTerritories(state, player)`.
  - `conquerTargets(state, player, anywhere) → string[]`: §6's legal targets, in map hex order: explored (R16), at most 1 outpost, not controlled by `player`, and next to a territory they control unless `anywhere`.
  - `loneOpponent(state, hex, player) → number | null`: the seat of a lone upright outpost of another seat on `hex`, if the hex holds exactly that one outpost.
